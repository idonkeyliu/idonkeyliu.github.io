浅谈shell,awk与sed

发表于 2017-09-30 | 分类于 运维 |

服务器上最高频的编程，往往不是写服务，而是把文本变成答案：日志、CSV、配置、进程列表。Shell、awk、sed 常被揉成「三种脚本语言」——更准的说法是三种职责。

一句话：Shell 管流程，sed 改行，awk 算列；角色分清，命令行才不会变成正则迷宫。

三者到底是什么

工具 核心角色 最适合
Shell（bash/zsh） 命令编排器 变量、条件、循环、启动程序、重定向
sed 流式文本编辑器 替换、删除、选取、简单逐行变换
awk 面向记录与字段的文本处理语言 分列、聚合、统计、格式化报表

Shell 像导演，负责“先做什么、失败怎么办”；sed 像校对，逐行修改；awk 像表格分析师，把每行当记录、每列当字段。

管道：把程序接成流水线

Unix 工具通常只做好一件事，并通过三条通道组合：

  • 标准输入 stdin：程序读取的数据
  • 标准输出 stdout：正常结果
  • 标准错误 stderr：诊断信息

数据从左向右流动：先筛错误行，再脱敏，最后只显示前十行。管道传递的是 stdout，默认不会传 stderr：

每一级都应有明确职责。若一条命令需要横向滚动三屏，最好拆成脚本、加中间变量和错误处理。

什么时候用哪个

先按问题形状选工具：

  1. 需要启动多个程序、判断成功失败：Shell。
  2. 每行做一次替换或删选：sed。
  3. 按列判断、累加、分组：awk。
  4. JSON：jq；YAML：yq。
  5. 复杂数据结构、网络请求、长期维护：Python/Go 等通用语言。

一个实用边界是：命令用于一次性探索很合适；一旦要进定时任务、会修改数据、需要测试和重试，就把它升级成有参数校验、日志和测试的脚本。

常见陷阱

引号层级

单引号阻止 Shell 展开，双引号允许 $variable、$(command) 展开：

awk 程序通常放单引号里，Shell 值通过 -v 传入。

正则不是通用解析器

HTML、JSON、CSV 都有结构与转义规则。sed/awk 可以处理受控的简单格式，但不应冒充完整解析器。

不要边看边破坏

先输出预览，再写文件；先备份，再用 -i；处理批量文件时用 NUL 分隔；把破坏性动作设计成可重复、可回滚。

小结

Shell、sed、awk 的共同美感是组合，而不是炫技。Shell 管流程，sed 改行，awk 算列；选择合适的数据工具，保持每一级管道简单，再用 set -euo pipefail、正确引用和预览机制兜住边界。

真正高质量的一行命令，不是字符最少，而是读者能快速回答：输入是什么、做了哪些变换、失败会怎样。
