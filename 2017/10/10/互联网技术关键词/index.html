互联网技术关键词

发表于 2017-10-10 | 分类于 技术 |

开会时有人甩出一个词——「我们上 Service Mesh」「这块用 CDC」「先做降级」——半桌人点头，半桌人其实在心里搜英文缩写。互联网技术不是缺文档，是缺一张不会让你慌的地图。

一句话：先把生词丢进篮子，再问「它治什么病、会留下什么副作用」；归类对了，精读才有意义。

这张图我按八个篮子收纳。每个词只给直觉，不替代专项深潜——但够你下次开会接得住话、问得出好问题。

怎么用

听到新词，做三步：

  1. 归类：它更像架构、数据、稳定性，还是云原生？
  2. 两句话：解决什么痛苦？引入什么成本？
  3. 再决定：要不要开专题——大多数词，归好类就不慌。

架构：系统怎么切、怎么活

词 一句话直觉
微服务 按业务边界拆成可独立上线的小服务；换来的是分布式复杂度
SOA 更早一代的「面向服务」；微服务可看作它的细粒度亲戚
中台 把复用能力沉下去；成了是杠杆，不成是又一层单体
高可用 部分挂了还能用——靠冗余、切换、降级，不是靠祈祷
CAP 分区发生时，一致性与可用性很难同时满分
BASE 大规模业务的老实话：先基本可用，最终一致往往就够

选型时别问「先进不先进」，问「我们的失败模式是什么」。

数据：存得下、取得快、流得动

词 一句话直觉
分库分表 水平切开扛量；跨库查询和事务会变疼
缓存 用空间换时间；穿透/击穿/雪崩是三道必答题
MQ 异步解耦与削峰；重复与乱序是标配作业
CDC 盯住数据库变更，把它变成下游事件流
OLAP / 湖仓 分析型查询的舞台；湖与仓在走向统一

数据域的坑，多半出在「一致性和时效」的夹缝里。

稳定性：流量打过来时你还站得住吗

限流是挡超额；熔断是下游病了就快速失败；降级是保核心、舍次要；容灾是机房级后手；SLA/SLO/SLI 把「稳」写成可测的承诺；混沌工程则是主动打针，验证你的假设是不是自我安慰。

稳定不是「从不失败」，是「失败时可预期、可恢复、可解释」。

云原生：交付与运行的现代默认项

容器把运行时打包；K8s 负责编排；Service Mesh 把重试、鉴权、可观测往边车沉；GitOps 让 Git 成为事实来源；可观测性离不开 Logs / Metrics / Traces；Serverless 让你少管机器——并接受冷启动与平台绑定。

云原生不是「上了 K8s 就原生」，是声明式、可观测、可回滚成为习惯。

工程效能：让「提交→价值」变短

CI/CD 缩短路径；代码评审传播质量与上下文；特性开关把「发布」和「放量」拆开；AB 实验用统计代替嗓门；技术债是今天的快捷换明天的利息——会借的人要会还。

安全：默认不信任，持续要证据

零信任不是口号，是每次访问都核验。SSO 管「你是谁」，RBAC 管「你能干什么」，2FA 让密码泄露不等于失守。加密保护传输与落盘；审计回答「谁在何时动过什么」。

性能：先对齐口径，再谈优化

QPS 是速率，RT 是时延，吞吐是单位时间干完多少活——三个人用三个定义开会，优化必歪。然后再盯 GC、连接池、CDN、锁与热点。没有测量的优化，都是玄学。

前沿（2020s）：新词也按同一套方法拆

词 一句话直觉
LLM 超强的「下一个词」预测引擎，不是万能真理机
RAG 先检索再建，给模型外挂可更新的书架
Agent 模型 + 规划 + 工具调用的闭环
MCP AI 外设的统一插口（工具/资源/提示）
向量库 存 Embedding，按「意思近不近」找邻居
边缘计算 把算力推到靠近用户和设备的地方

新词吓人，是因为它还没被你归类；归进篮子后，大多是老问题的新接口。

把关键词连成一条真实链路

想象一个电商系统：用户请求先到 CDN 和网关，前者就近缓存静态资源，后者负责认证、限流与路由。核心业务最初可以是单体；团队和流量增长后，再按订单、库存、支付等领域边界拆成微服务。

下单数据写入关系数据库，热点商品进入 Redis。订单创建后通过 MQ 发布事件，通知与画像异步处理；数据库变更由 CDC 同步到搜索和分析平台。这里每个词都不是孤岛：缓存提升读取速度，却引入一致性问题；MQ 解耦流程，却要求幂等、重试与堆积治理；分库分表突破容量上限，却让跨分片查询和事务更难。

运行层面，应用打包进容器，由 Kubernetes 维持副本。CI/CD 将提交变成制品，金丝雀发布只放少量流量，指标异常便回滚。日志解释细节，Metrics 展示趋势，Trace 串起一次请求：三者共同组成可观测性，而不是彼此替代。

稳定性也会形成闭环：限流把压力挡在入口，熔断阻止故障扩散，降级保住下单主链路，异地容灾应对地域事故。团队用 SLI 测量成功率和延迟，以 SLO 设目标，再用错误预算决定继续发版还是优先还可靠性债。

容易混淆的几组词

并发、并行、异步

  • 并发：多个任务在同一时间段推进，单核切换也可以并发。
  • 并行：多个任务在同一时刻真正执行，通常依赖多核或多机。
  • 异步：发起方不原地等待，结果稍后通过事件、回调或 Future 返回。

三者描述不同维度。异步 I/O 可以提高并发，却不保证 CPU 计算并行。

认证、授权、审计

认证回答“你是谁”，授权回答“你能做什么”，审计回答“你做过什么”。SSO 简化统一登录，RBAC 按角色授权，最小权限则要求只开放完成任务必需的能力。

备份、高可用、容灾

备份让数据可以恢复；高可用减少组件故障造成的中断；容灾面向机房、地域级事故。主从复制不是备份——误删除也可能迅速复制到从库。任何方案都应明确 RPO（最多能丢多少数据）与 RTO（多久必须恢复）。

选型时问四个问题

技术概念都在做交换：用空间换时间，用一致性换可用性，用基础设施复杂度换团队自治。遇到新词，可以追问：

  1. 它解决哪个可量化问题：P99 延迟、发布频率，还是恢复时间？
  2. 不用它会怎样：如果单体已经稳定，微服务也许暂时没有收益。
  3. 复杂度转移到哪里：Serverless 少管机器，却仍要管冷启动与平台边界。
  4. 谁来长期维护：能跑 Demo 不等于团队能值班三年。

学习一个词时，试着用自己的话写一句定义，画出上下游，再列出至少两个失败模式。能解释它“不适合什么”，通常才算真正理解。

小结

技术关键词是行业的压缩包。顶流不是背完词条，而是听到任何词都能迅速定位坐标系。把这张图当目录，专项文章当章节——下次有人甩术语，你可以微笑着问：它治的是哪门病？
