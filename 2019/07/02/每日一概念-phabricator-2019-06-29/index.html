Phabricator

很多团队的研发协作是拼盘：Git 一处、评审一处、任务又一处。讨论飘在聊天群，半年后没人说得清「这行代码为什么这样改」。Phabricator 想把「一次改动」从讨论、评审到落地，钉在同一扇门里。

一句话：以 Diff 为中心的开源研发门户——Differential 管评审，Maniphest 管任务，仓库与文档还能同住。

是什么

Facebook 开源的工程协作套件（现社区维护）。核心体验：变更以 Diff 为中心。开发者上传差异，评审人在 Differential 里逐行讨论；任务与缺陷走 Maniphest；再配合仓库浏览、文档 Wiki，形成闭环。

为什么重要

它影响过整整一代工程文化：强制评审、变更可追溯、争论钉在具体 diff 上。今天你在 GitHub/GitLab 的 MR + Issue 里看到的骨架，不少都能在这里找到亲戚。工具会换，「以变更为中心」的语言还在。

怎么理解

别把它当成过气软件怀旧，而当成一套工作流语法：谁提出变更、谁批准、任务如何挂上 diff、上线后如何回看。学它，是为了审视你现在的评审是「走流程」，还是「真的把决策留在了可检索的地方」。

常见误解

  • 「我们不用 Phabricator 就不用懂」：你用的 MR 流程很可能是它的精神续作。
  • 有工具=有文化：没有强制且有质量的评审，换什么平台都一样飘。

一句话记住

Phabricator = 把 Code Review、任务与仓库缝成一件事的开源前辈。
